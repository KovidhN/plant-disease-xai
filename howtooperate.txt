PLANT DISEASE XAI — HOW TO OPERATE
Updated: 2026-11-13

PROJECT FOLDER
---------------
Open PowerShell and change to the project folder:

    Set-Location "C:\path\to\Plant XAI"

The project virtual environment is in .\venv. Use its Python executable in the
commands below so you do not depend on which Python is first on PATH.


1. START THE STREAMLIT APP
--------------------------
Run from the project folder:

    .\venv\Scripts\python.exe -m streamlit run app.py --server.port 8501

Open this address in your browser:

    http://localhost:8501

Keep the PowerShell window open while you use the app. To stop the server,
focus that window and press Ctrl+C. To use the app again later, run the start
command again.

If port 8501 is already occupied, use another port:

    .\venv\Scripts\python.exe -m streamlit run app.py --server.port 8502

Then open http://localhost:8502. Old browser tabs on port 8765 may be stale;
use the port printed by the Streamlit command.

Check whether the app is responding:

    Invoke-RestMethod "http://localhost:8501/_stcore/health"

Expected response: ok


2. START AND CHECK LOCAL OLLAMA
-------------------------------
Ollama may already be running in the background. Check its installed models:

    ollama list

Or check the local HTTP API:

    (Invoke-RestMethod "http://localhost:11434/api/tags").models | Select-Object name

The configured model is qwen2.5:3b. If it is not installed, download it once:

    ollama pull qwen2.5:3b

If the API is not reachable, open a second PowerShell window and run:

    ollama serve

Leave that window open as well. If it says the port is already in use, Ollama
may already be running; recheck /api/tags rather than starting another server.

The app reads OLLAMA_BASE_URL and OLLAMA_MODEL from .env. Defaults are
http://localhost:11434 and qwen2.5:3b. Disease predictions request an advisory
with a 120-second timeout. Healthy predictions skip Ollama. On connection,
HTTP, or invalid-advisory errors, the decision layer uses local deterministic
rules and displays a status reason in the advisory area.


3. OTHER USEFUL COMMANDS
------------------------
Run all project tests:

    .\venv\Scripts\python.exe -m pytest tests -q

Classify one image from the terminal (top three predictions):

    .\venv\Scripts\python.exe predict.py "C:\full\path\to\leaf.jpg"

If the checkpoint is not found automatically, give its path explicitly:

    .\venv\Scripts\python.exe predict.py "C:\full\path\to\leaf.jpg" --checkpoint ".\trained instnace\mobilenetv2_plant_disease.pth"

Check that the trained checkpoint exists:

    Test-Path ".\trained instnace\mobilenetv2_plant_disease.pth"

Install/restore the project dependencies if needed:

    .\venv\Scripts\python.exe -m pip install -r requirements.txt


4. OPTIONAL FASTAPI SERVICE
---------------------------
The Streamlit dashboard runs by itself; FastAPI is not required for it.
The optional legacy API exposes /, /predict, and /analyze. Start it with:

    .\venv\Scripts\python.exe -m uvicorn main:app --reload

Open API documentation at http://127.0.0.1:8000/docs.

IMPORTANT: the legacy API initializes a separate model path from MODEL_PATH
(default: models/mobilenetv2_plant_disease.pth) and may use a mock path if its
checkpoint is absent. Before relying on API predictions, configure MODEL_PATH
in .env to the actual checkpoint and check the API's model_loaded/is_mock
status. Do not assume the API is using the same model-loading path as the
standalone Streamlit dashboard.


5. CHECKPOINT PATH NOTE
-----------------------
The Streamlit model utility searches known locations, including:

    .\mobilenetv2_plant_disease.pth
    .\trained instnace\mobilenetv2_plant_disease.pth

An invalid MODEL_PATH from .env is logged as a warning, after which those
known Streamlit checkpoint locations are searched. If you want to avoid that
warning and make the configuration explicit, update MODEL_PATH in .env to the
checkpoint's full path. The current directory name is spelled "trained
instnace". Do not share or commit .env; it may contain private credentials.

PROJECT OVERVIEW
This is a prototype decision-support application for plant-leaf images. The
main user-facing demo is a local Streamlit dashboard, with MobileNetV2 image
classification, Grad-CAM visual evidence, and a structured language-model
advisory. It is implemented to run locally on CPU; CUDA may be used if
available. The dashboard does not require the separate legacy FastAPI service.
It is a student-project demo, not a validated diagnosis or field-ready
agricultural product.

IMPLEMENTED FEATURES
1. Image input: upload JPG/JPEG/PNG or capture an image using Streamlit's
   camera input.
2. Preprocessing: RGB conversion, 224x224 resize, ImageNet normalization
   (mean [0.485, 0.456, 0.406], std [0.229, 0.224, 0.225]).
3. Classifier: PyTorch MobileNetV2 with 38 PlantVillage output classes and a
   supplied trained checkpoint. The expected local checkpoint is
   "trained instnace/mobilenetv2_plant_disease.pth" (directory spelling is
   exactly "instnace"). It runs on CPU without requiring a GPU.
4. Results: top-three class predictions and confidence percentages.
5. Species filter: optional filtering and re-normalization over classes for
   the selected species. The resulting confidence is conditional on the
   user's selected species; this is not an independent species detector and
   does not retrain the classifier.
6. Explainability: class-targeted Grad-CAM on MobileNetV2.features[-1].
   The interface displays the resized original, standalone raw heatmap, and
   blended overlay. Metrics include target class/layer, normalized peak and
   mean activation, percent of pixels over 0.5, and the share of such
   activations within the centered 70% image region. These metrics describe
   the visualization only; they do not prove causal reasoning or measure
   disease severity.
7. Decision/advisory layer: for a non-healthy classifier prediction, sends
   structured evidence (predicted label, confidence, top three, Grad-CAM
   coverage) to local Ollama's /api/chat endpoint. The configured default is
   qwen2.5:3b; request timeout is 120 seconds, with a compact JSON response.
   The response contains reliability, severity, routing, issue explanation,
   recommended preliminary action, and a Hindi summary. The model's predicted
   disease label is preserved; the advisory must not replace it. A healthy
   prediction skips Ollama. When the request fails or returns invalid data,
   deterministic local rules are used and a status reason is displayed.
8. Hindi speech: gTTS can generate MP3 audio for the Hindi summary and the
   app caches generated audio in Streamlit session state. Speech generation
   requires network access; failure leaves the text available and shows a
   graceful caption.
9. UI: warm beige, forest green, plum accents, geometric typography, and
   neumorphic cards in the Bauhaus-inspired dashboard. Preserve descriptions
   as current app behavior; do not propose redesigning the existing theme.
10. Optional CLI: predict.py classifies an image and prints top-three results.
    An optional FastAPI backend exists separately. Inspect its actual code
    and tests before making claims about it; it has distinct model-loading
    behavior and may use a mock path if its expected checkpoint is absent.
